# 病历处理全流程（图转文补全 → 脱敏 → 提取 → 规则检查）

本技能**自包含**，不读取、不修改其他技能（含 `medical-record-structuring`）的任何文件。
两阶段推进：**阶段一**产出图转文/补全/脱敏产物；**阶段二**按用户提供的字段 excel 做提取与规则检查。

## 输出目录与命名规范（重要）

**病历名 = docx 文件名去掉扩展名**（含其中的编号/姓名，原样保留）。命名必须与输入病历一一对应，禁止自拟简称：

| 对象 | 命名规则 | 示例（输入 `703386 无胱抑素 李军.docx`） |
|---|---|---|
| 输出目录 | `output/<病历名>/`（每份 docx 独立，开始前确认不存在或为空） | `output/703386 无胱抑素 李军/` |
| 图转文产物 | `<病历名>_图转文.md` | `703386 无胱抑素 李军_图转文.md` |
| 补全产物 | `<病历名>_补全.md` / `<病历名>_补全报告.txt` | `703386 无胱抑素 李军_补全.md` |
| 脱敏产物 | `<病历名>_脱敏.md` / `<病历名>_脱敏.docx` | `703386 无胱抑素 李军_脱敏.docx` |
| 阶段二汇总表第一列 | 「文档标题」的值 = **病历名**（去扩展名），每行一份 docx | `703386 无胱抑素 李军`、`703530 无胱抑素 李雪飞` |

- `supplement.py` 已自动按 docx 文件名生成产物前缀，**不要手工改名**；掩码/转 docx/汇总等步骤的文件名由调用方按上表传入。
- 敏感词中间产物（`敏感词.txt` / `手动词*.txt` / `敏感词清单.txt`）放在同一目录内，名称不变。

## 阶段一：图转文 + 补全 + 脱敏

### 1. 图转文 + 本地增量补全

```bash
PY="C:/Users/dongyi.qiu/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
SKILL="<本技能目录>"
"$PY" "$SKILL/scripts/supplement.py" "<docx绝对路径>" "<输出目录>" [--debug]
```

产出三件：
| 文件 | 说明 |
|---|---|
| `<名称>_图转文.md` | MinerU 原始结果（对照用） |
| `<名称>_补全.md` | **补全后的最终产物**（补入内容有 `<!-- 本地 OCR 补充识别 -->` 标注） |
| `<名称>_补全报告.txt` | 审计：逐图判定与补入明细 |

**补全机制**（详见脚本头注释）：
- **粗筛**：该图 md 缺「正文锚点」（检查所见/报告结果/备注/检查日期/超声测值）→ 需补。
  （"检查项目/申请时间/检查人"属面板字段，**不作判据**）
- **本地 OCR**：rapidocr 全图识别，2x 放大；坐标换算回原图系。
- **四重过滤**：① 行级 n-gram 覆盖率 ≤0.5 ② box 中心 x > 图宽×0.5 ③ 锚点 y 带界定正文区
  ④ 噪音正则（纯数字/日期/本机IP/服务器/医院系统名）。
- **只增不减**：MinerU 已识别内容一字不动；正常图（锚点齐全）直接跳过。

> **实测坑位：医院名可能只存在于图片层。** EHR 截图的**窗口标题栏**（形如
> `XX医科大学第二附属医院-医技工作站`）既不被 MinerU 转成文本，也不在补全的采纳区内
> （补全只取右侧正文区 `x > 图宽×0.5`），因此 LLM 无从识别、文本层也永远不含该词。
> 阶段一结束后建议补一步**整图**复核：对 docx 内嵌图做整图 rapidocr，用
> `医院|医科|附属|卫生|保健` 扫一遍；命中词并入 `--manual` 词表
> （即使文本层不含该词，掩码是空操作，但会记入敏感词清单，可据此向用户说明
> "医院名仅在截图标题栏，文本交付物不含，如需遮盖请另行处理图片层"）。
>
> **2026-09-16 在 5 份样本（703530 / 703543 / 703641 / 钟广章 / 703386）上实测确认**：
> EHR 截图**每一张**的窗口标题栏都是 `XX医院-医技工作站`（该院为「海南医科大学第二附属医院」），
> MinerU 文本层一律不含该串。同时确认：`md2docx.py` 产出的 `<名称>_脱敏.docx` **不含任何图片**
> （zip 内 `media` 条目为 0），所以**文本交付物天然不带图片层**；但**原始 docx 的截图仍含全部姓名**，
> 需提醒用户不要外发原始文件。
>
> **2026-09-17 用 `scripts/image_scan.py` 对同 5 份 docx 做整图复核修正上述描述**：
> 113 张内嵌图整图（2x）rapidocr 后，标题栏命中的**不是**完整院名串，而是被 OCR 切成的碎片
> —— 全部 5 份都稳定命中 `海南医科` + `大学第二附属`（另外还命中 `海南医学院第二附属`、
> 描述性语句 `遂至当地医院` / `发病以来未曾前往医院` / `请在公众号医院` 等，后者由
> `_GENERIC_CONTAINS` 正当过滤）。因此 `--manual` 应补的是这两条碎片（掩码空操作、只记清单），
> 而**不是** `XX医院-医技工作站`。该院完整院名在**文本层**另有出现（页面页眉），已由后缀回溯法
> 正常抓到，不受影响。

### 2. 敏感词识别

**引擎选择（2026-09-16 起默认 code）**：

| 引擎 | 命令 | 状态 | 说明 |
|---|---|---|---|
| **代码引擎（默认）** | `sensitive.py`（不带 --engine） | ✅ 默认 | 本地正则识别，0 网络、秒级、无 GPU 争抢。2026-09-16 在 4 份样本上验证：人工词表 100% 覆盖、患者名 N→0、漏网复扫 0 残留 |
| LLM 引擎（备份） | `sensitive.py --engine llm` | 备份 | 原三段合并流程（正则 + 分块调 Ollama qwen3:14b + 手动词）。远程资源空闲后加 `--engine llm` 切回，其余参数不变。`--no-llm` 保留为兼容别名 = code 引擎 |

两个引擎输出文件格式一致，下游 `mask.py` 无需改动。

```bash
# 默认（代码引擎）：
"$PY" "$SKILL/scripts/sensitive.py" "<_补全.md>" "<敏感词.txt>" [--manual "<手动词.txt>"]
# 备份（LLM 引擎，Ollama 恢复可用后）：
"$PY" "$SKILL/scripts/sensitive.py" "<_补全.md>" "<敏感词.txt>" --engine llm [--model qwen3:32b] ...
```

- **代码引擎识别手段**（供排查时参考）：
  ① 医院名：后缀锚点（医院/卫生院/保健院/门诊部/诊所/卫生服务中心/卫生室/医务室/卫生所/保健所）
     向前回溯取全名，通用词（上级/当地/本院等）自动过滤；回溯吞进的前导动词/主语
     （患者/遂至/遂往/发病后/未曾前往…）由 `_normalize_hospital` 逐层剥掉；
     候选若含 `_GENERIC_CONTAINS`（当地/本院/上级/我院/公众号…）则整体弃用
     —— 描述性语句（「患者遂至当地医院」「发病以来未曾前往医院」）不再被整段吞掉，
     `--verify` ③ 项同口径，不会把它们反复报成漏网；
  ② 患者姓名：`姓名[:：]` 锚点 + **文件名自动提取**（病历名去掉产物后缀段后的最后一个中文段，
     如 `703386 无胱抑素 李军_补全.md` → 取「李军」，项目词「无胱抑素」自动跳过），mask.py 全局掩码；
  ③ 医护姓名：`医师/医生/护士/签名` 角色锚点（要求带冒号，保守防误报）；
  ④ 号码类：床号/住院号/手机号/ID/地址 + 无标签床号（`数字+床`，已加 `(?<![\d\-—])` 负向断言，
     避免把 `2025-04-2800 床…` 这类日期残片误当床号）、括号流水号（`(数字)`）——已内置；
  ⑤ `--manual` 手工补齐词合并（每行一个）。
- **锚点贪心多吞字的修正**（`_clean_name`，2026-09-17 修）：锚点正则的 `([一-龥·]{2,4})` 是
  贪心的，紧跟姓名的字段标签会被吞进来 —— `姓名：李雪飞性别：女` → 候选「李雪飞性」、
  `葛广全主任医师` → 候选「葛广全主」。直接掩码会把「性别」的「性」、「主任」的「主」一起抹掉，
  破坏字段标签。现 `_clean_name` 先剥尾部整词标签（性别/年龄/医师/主任/主治/签名/床号…），
  再剥尾部单字标签（性主当师士期号别，仅当总长 4 且剥后 ≥3 字）。修正后患者名计数由 2~3 降为 1、
  「███性别：女」标签完整。`--verify` ①② 同用 `_clean_name`，两侧口径一致。
- **表头词黑名单**（`_NAME_BLACKLIST`，2026-09-16 扩充）：角色锚点前的 `\s*` 会跨行吞字
  （「签名：\n\n日期：」把「日期」当人名、重签行把「医师签名」当人名），已把
  日期/时间/医师签名/医生签名/护士签名/签名/记录者/创建者/操作者/以上/无… 列入黑名单；
  `--verify` 的 ①② 项同步套用 `_clean_name`，两侧口径一致，空签行不再反复报假漏网。
- **表格内检验/审核人员姓名**（代码引擎抓不到，必补 `--manual`）：EHR 检验列表里「检验人/审核人」
  列是**无标签裸单元格**（如 `<td>邱丽莉 2</td>`），锚点法失效。补法：扫 `<td>汉字{2,4}数字?</td>`
  形态的单元格，剔除「单据/样本/血清/检验人/项目/葡萄糖…」等表头与指标词后即为姓名；
  同一医院各病历医护重叠，可跨病历取并集交叉核对（见「五份样本实测」）。
- **多次住院病历**：每个住院号的床号/流水号都不同，代码引擎已自动扫上述两类无标签模式，
  但仍可能有其他 OCR 变体漏网，谱词后在脱敏文件上复扫补齐再重跑掩码。
- **五份样本实测（2026-09-16，可作补词清单模板）**：一份病历的医护名通常只有 10~25 个，
  但**真正需要 `--manual` 的往往过半**。可靠的补词顺序：
  1. 跑 `sensitive.py` 得代码词表；
  2. 扫「角色相邻」（`X 主任医师/主治医师/签名/护士/规培医师`，代码锚点要求冒号，无冒号即漏）；
     用 `scripts/scan_candidates.py` 三路合并扫描（A 角色相邻 / B 表格裸单元格 / C 相似变体）
     生成候选，`scripts/ctx_dump.py` 导出候选上下文供人工判定；
  3. 扫「表格裸单元格」（`<td>汉字{2,4}数字?</td>`，抓检验人/审核人）；
  4. 扫「相似变体」（与已识别姓名共享 ≥2 字，抓 OCR 错字：土石坚→王石坚、王石三→王石坚、
     苗广全→葛广全、翁量娜→翁曼娜、吳曾繁→吴曾繁、土彦双→王彦双、相明冠→林明冠）；
  5. **扫「非签名类角色锚点」**（`scripts/role_scan.py`）：`检查人/申请人/术者/报告人/核对人/
     录入人/创健人` 等锚点不在 `_ROLE_RE` 内，是真实漏名来源 —— 2026-09-17 实测抓到
     徐惠/吴多杏/周德兴/付洁莹 4 个新名。跑完这一步再补 `--manual`；
  6. **加「名部安全网」**（`scripts/name_tail.py`）：把词表里每个 **3 字中文全名**的名部（末 2 字）
     也并入 `--manual`。长词优先保证全名仍按全名掩码，名部只兜底「被更长变体截断后留下的残片」
     与 OCR 掐字（`郭义龙`→`部义龙`、`吕有凯`→`邑有凯`、`葛广全`→`葛广`）。脚本 `--report`
     会列出「名部出现次数 > 全名次数」的名部供复核（通常是 OCR 变体导致的正常差值）；
  7. 用 `--verify` + `scripts/frag_check.py` + `scripts/residual_scan.py` 收口。
  七步做完，患者名 100% 归零、复扫 0 残留、姓名残片 0（仅剩「海南」这类省份词属良性误报）。
- **代码引擎已知盲区**（人工核对敏感词清单时重点看）：手写签名区无标签裸名、OCR 错字变体
  （医院/姓名被识别错）、非常规机构名（体检中心/康复中心等不在后缀表内）——靠 `--manual` 补齐；
  后缀表/锚点正则在 `sensitive.py` 顶部常量区（`HOSPITAL_SUFFIXES` / `_GENERIC_PREFIX` /
  `_NAME_BLACKLIST`），可按需扩充。

#### 阶段一辅助脚本（`scripts/`，全部本地、0 网络）

| 脚本 | 用途 |
|---|---|
| `scan_candidates.py` | 三路候选扫描（角色相邻 / 表格裸单元格 / 相似变体） |
| `ctx_dump.py` | 候选词上下文导出（人工判定是否真名） |
| `role_scan.py` | 非签名类角色锚点后姓名扫描（检查人/申请人/术者…），并标注「不在词表」 |
| `name_tail.py` | 名部（末 2 字）安全网生成 + 撞普通词复核（`--report`） |
| `image_scan.py` | 整图 rapidocr 复核图片层医院名（见上「实测坑位」） |
| `frag_check.py` | 姓名残片检测（脱敏后是否仍含已识别姓名的 ≥2 字子串） |
| `residual_scan.py` | 掩码块/锚点紧邻未掩汉字扫描（`--verify` 的盲区补充） |
| `chk_mask.py` | 验收：患者名归零 + 词表无死词 + 脱敏残留 0 + 掩码字符数 |
| `test_mask.py` | `mask.py` 回归自测（11 例：标签保留 / 连排整段掩码 / 黑名单 / 幂等）；改掩码逻辑后必跑 |
- 以下仅 LLM 引擎（备份）适用——**模型选择与降级（默认 qwen3:14b + num_ctx 8192）**：
  - 32b 约需 19.7GB 显存，MinerU 权重常驻显存时 32b 加载即报 `cudaMalloc failed`；
    14b（约 10GB）实测可稳定加载。显存充裕时可用 `--engine llm --model qwen3:32b` 升级。
  - 14b 也报显存不足：① 先跑完 MinerU 任务或稍后重试；② `--model qwen3:8b`；③ 改回代码引擎。
  - `--num-ctx` 默认 8192：**14b 在 16384 下可能"全过程无报错、但返回 0 词"**（实测坑）。
    调大 num_ctx 或换模型后**必须核对词数**。
  - LLM 输出有随机性，**凡是能从正文肉眼确认的姓名/编号，全部固化进 `--manual`**。

### 3. 掩码脱敏

```bash
"$PY" "$SKILL/scripts/mask.py" "<_补全.md>" "<敏感词.txt>" "<_脱敏.md>" "<敏感词清单.txt>"
```

- 等长 `█` 掩码；长词优先；词内允许夹空白（容错）。
- **锚点整段掩码**（`mask_anchor_runs`，2026-09-17 新增，在词表掩码**之前**执行）：
  EHR 签名区常把同一次操作的两个姓名连排（`医师签名：姚富会姚宫会`），OCR 还会串字
  （`上级医师签名：张秋张秋林`）。词表法只能枚举有限变体，一旦 4 字变体先匹配，就会把
  3 字真名的尾字留下（`███` + `宫会`）造成 1~2 字残片泄漏 —— 而 `--verify` 用
  `[一-龥·]{2,4}` 抓锚点后汉字，`█` 不在字符类内，**这类残片是 `--verify` 的盲区**。
  故 `mask.py` 现先对「角色/签署锚点 + 冒号」后紧跟的 2~6 字汉字整段掩码，掩码前先剥尾部字段
  标签（同 `_clean_name` 口径）以免抹掉「性别」等标签；锚点表含
  签名/医师/医生/护士/护师/技师/姓名/记录者/创建者/创建人/创健人/操作者/检查人/检验人/审核人/
  申请人/申请者/术者/报告人/核对人/录入人/送检医师/检验医生/审核医生/手术医师/麻醉医师。

### 5.5 超长行重排（阅读副本，阶段二前置）

`Read` 对**单行 >2000 字符**静默截断。MinerU 把整张表序列化在一个物理行里（本语料 4644~7831 字符/行，
占全文 71%~82% 字符量），所以超长行 100% 是信息密度最高的检验单/病程/出院记录，**必须重排后才能一次读全**。

```bash
"$PY" scripts/unwrap_md.py "output/<病历名>/<病历名>_脱敏.md" "output/<病历名>/<病历名>_可读.md"
# 默认 --limit 1800 --lookback-max 400 --ratio 0.6 --guard 100
# 退出码：0 通过 / 1 守恒失败 / 2 行长超限 / 3 标签被切断 / 4 参数非法
```

- 只在断点后插入换行，**去掉换行后与原文逐字符相同**；原 `_脱敏.md` 不动。
- 车道分流：表格行切在 `</td>|</tr>|</table>|</p>` 之后；文本行切在 `。！？` 之后（尽力，回看 ≤400 字符）。
- **接线四原则**：① 每次重建，不复用旧副本；② 硬红线失败 → 该份**回退读 `_脱敏.md`** 并告警，不中断阶段二；
  ③ 真值锚定不变（results.json 的 `文档标题`、行序、规则检查、xlsx 列仍锚定病历名与 `_脱敏.md`）；
  ④ **`_可读.md` 绝不喂给 `md2docx.py`**（插入的换行会在转 docx 时产生多余断行），正式交付物始终是 `_脱敏.md`。
- 实测收益（5 份 / 44 条超长行）：总耗时中位 **46.54 s → 34.90 s（−25.0%）**，截断补看往返 **9 次 → 0 次**；
  验收 R1 守恒 5/5、R4 标签 12613 个跨段 0、R5/R6 59 处换行点违规 0、幂等 5/5、碎片 0。

### 6.5 「有/无 + 具体描述」型字段（v2 表头 2026-09-17 起）

部分表头把描述列写成硬规则，例如：
`登记出院记录中出院诊断、入院记录中现病史和入院记录中既往史里高血压相关内容。(1)若有…(2)若否认…(3)若无描述，输出"无"并具体描述为：/`

执行口径（已在 28 份批次落地）：

1. **有/无 用代码判**（三级证据优先：出院诊断 ＞ 现病史 ＞ 既往史），描述用模型定稿；
2. 单元格格式固定为 **`有/无，<来源>：<原文片段>`**，来源缺失时填 `无，/`；空病历整列 `无`；
3. 定稿前先跑 `htn_dm_evidence.py` 拿四来源原始上下文（**不要**只看断句片段，会丢「否认」二字导致反向误判）；
4. 组装脚本内置自检：**判「有」却无描述**、**判「无」但描述非否定句** 都要打印告警。

**必须防的 5 个坑（都已在真实批次踩到）**：

| 坑 | 现象 | 处理 |
|---|---|---|
| 现病史窗口写死长度 | `现病史[:：](.{4,1500})` 会把正面的「有高血压病史20年余」截掉（该份现病史很长） | 窗口一律**截到下一节标题**，不用固定字数 |
| 出院诊断无标签 | 个别病历出院诊断藏在出院记录里，标签是「二、诊断：」，正则匹配不到 | 有现病史/病程证据时以现病史为主，描述里并列注明 |
| 家族史污染 | 「否认家族成员有…糖尿病…」被当成现病史 | 每个窗口都要 `split(家族史|个人史|婚育史|流行病学史)[0]` |
| 护理单名污染 | 护理记录单名「糖尿病毛细血管全」「糖尿病手细血管仝」等的 OCR 变体 | 建 `FORM_NOISE` 词表，长度不定，需持续补变体 |
| 阴性/噪声命中 | 出院医嘱健康教育句「慢阻肺和糖尿病、高血压一样…」 | 命中后必须回看上下文，不能只看关键词命中 |

### 6.5.1 时间列要求「精确到时分秒」时（v3 表头 2026-09-17 起）

表头会在时间列后缀 `(精确到时分秒）`。此时不能只给日期，要**回源找完整时间戳**：

| 来源 | 位置 | 备注 |
|---|---|---|
| 超声/检查类 | 报告备注行 `检查日期：YYYY-MM-DD HH:MM:SS 检查人：… 检查诊室：…` | 首选 |
| 超声/检查类 | 报告表格行 `检查项目：… 申请时间：YYYY-MM-DD 00:00` | 备选，**常只有 00:00** |
| 检验类 | `检验单列表.txt` 单据表**末行**（倒序 → 首次）的「申请时间」列 | 列号定位见 6.5.2 |

**该院 OCR 的时间破损写法（必须归一化，否则会误判成「没有时分秒」）**：

- 日期与时间粘连：`2025-09-0514.55:45`、`2025-08-1007:46:56` → 先按 `\d{2}[:.]\d{2}[:.]\d{2}` 切开；
- **句点代替冒号**：`14.55:45` → `14:55:45`；
- 日期丢首位：`025-08-11 09:00:43` → 补成 `2025-08-11 09:00:43`；
- 确实只有日期（`申请时间：2025-07-14 00:00`）→ 按原文填 `00:00:00`，**并在交付说明里列为待复核**，
  不要自行编造时间。

### 6.5.2 单据表取列必须按表头行定位，不能写死列号

单据表正常 10 列（`□|单据|样本|检验人|检验时间|审核人|核收时间|申请人|申请时间|打印次数`），
「申请时间」在索引 8。但个别病历（实测 `608207`）**表头被 OCR 打散、行首多出若干空列**，
此时索引 8 取到的是「检验时间」而不是「申请时间」——两者都带时分秒，**错了也看不出来**。

正确做法：先在表内找含 `申请时间` 的表头行，用 `cells.index("申请时间")` 得到列号，再套到数据行。
「单据名称」表头线索也可能退化成 `?`，所以**不能只靠表头线索匹配**，要退化为「行内容含关键词」匹配。
脚本 `lab_apply_time.py` 已实现（实测 26/26 命中完整时间戳）。

### 6.5.3 三个高频字段的确定性取法（2026-09-17 实测修正）

**① 入院记录类型**：该院 EHR 每次入院的**文书标题**会写
`入院记录` / `再次入院记录` / **`多次入院记录`**（患者有多次入院时）。
表头若注明「若为『有多次入院记录』其类型归类为『再次入院记录』」，则：

```
标题 ∈ {多次入院记录, 再次入院记录} → 再次入院记录
标题 = 入院记录                      → 入院记录
```

判定标题时必须加锚：`(多次|再次|)入院记录` 之后 80 字内要出现 `姓名:` / `入院时间:` / `主诉:`，
否则会把侧栏导航项 `入院资料入院记录(已打印)` 误当标题。
⚠️ 实测有**文件名与文书标题矛盾**的情况（文件名写「第一次入院」、标题写「再次入院记录」）——
以**原文标题**为准，并在交付说明里列出矛盾项让用户定口径。

**② 主诉**：**不要要求结尾带句号**。原文常见 `主诉：反复胸闷痛2年余，再发3天 现病史：…`（主诉后无句号），
用 `主诉[:：]\s*([^。\n]{2,60}。)` 会**整条漏取**（实测 28 份里漏了 3 份）。
正确写法：锚点后用下一节标题断句 —— `现病史|既往史|个人史|病史陈述者|就诊时间|病例特点`，
再统一去掉结尾标点，保证同一列口径一致（脚本 `chief_complaint.py`）。
漏取时优先怀疑「结尾标点假设」，而不是以为原文没有主诉。

**③ 超声检查类型**：规则是「**扫描该报告的『检查所见』**，出现『床旁』→ 床旁心脏；否则输出**检查项目的内容**」。
原文项目名可能带部位后缀（`心脏彩超_心脏`、`床旁心脏_心脏`），按规则应原样输出；
若表头补注写「值一般为床旁心脏或者心脏彩超」，说明用户可能想要**去掉后缀**的形态 ——
两者只能选一个，**按规则原文取原样值，并在交付说明里给出「一键去后缀」的选项**，不要自行裁剪。

⚠️ **实战事故（2026-09-17，28 份里错 2 份）**：该列在首轮被一次性人工定稿写进 `OVERRIDE` 字典，
当时**只看「检查项目」字段、没有真正扫描「检查所见」**，于是
`608207 黄玉香`、`599534 林举伟`（检查项目=心脏彩超_心脏，但检查所见写「床旁超声检查，床边仪器条件有限…」）
被错判为心脏彩超，且该错误在 v2→v5 **一路继承**（因为换版只重做「有差异的列」，这列一直走复用路径）。
正确做法：**用 `echo_type_scan.py` 确定性推导**（切超声报告块 → 扫检查所见 → 有无「床旁」），
并在每次交付前跑一次自检：

```bash
"$PY" "$SKILL/scripts/echo_type_scan.py" batch_names.txt output timing/echo_scan.json \
      --check "output/病历信息提取vX_结果_*.xlsx"     # 退出码非 0 = 有列与重扫不一致
```

注意原文下划线常被 Markdown 转义（`心脏彩超\_心脏`），比较前要归一化 `\_` → `_`，否则会报一堆假差异。

### 6.5.3 图转文产物里的 HTML 实体与「跨单元格切断」（2026-09-18 事故）

MinerU 把表格还原成 HTML（`<td></td>`），并**对特殊字符做实体转义**，于是原文里的
`平均E/e'=9.84` 在 md 里变成：

```
…侧壁侧e&#x27;：-7，a&#x27;：-12，平均E/e&#x27;</td></tr><tr><td colspan="2">=9.84。
```

**三重麻烦（只解码还不够）**：

1. `'` → `&#x27;`、`"` → `&quot;`（实体转义）；
2. **指标名与数值被切到相邻两个单元格**（`</td></tr><tr><td>`）；
3. **更坏的情况：中间还夹了一个垃圾单元格**（实测 `574862`：
   `平均E/e&#x27;</td></tr><tr><td>_██ 2022-05-2400:00心脏彩超_心脏</td><td>=7.57。`），
   名字与值隔了整整一格。

**正确读法（`ee_extract.py` 已实现）**：

```python
t = html.unescape(raw)                  # ① 实体解码
t = re.sub(r"</t[dh]>", "\t", t)         # ② 表格压平：单元格→制表符
t = re.sub(r"</tr\s*>", "\n", t)        #    行→换行
t = re.sub(r"<[^>]+>", " ", t)
# ③ 跨格缝合：名字后先看同格，再看后 1~3 格找 `=数值`，最后退化为 1~60 的裸数值
#    （裸数值必须排除日期/时间/负值：用 (?<![\d\-:.：])(\d{1,2}(?:\.\d+)?)(?![\d\-:.])）
```

**配套铁律**：
- **禁止用硬编码字面量取值**（旧实现是 `"5.27" if "平均E/e'=5.27" in s else "无"` ——
  只因为某份文本恰好长这样才取到 1 份，另 2 份真值 7.57 / 9.84 全丢）；
- 取不到值时，**先怀疑实体/标签切断，再怀疑原文没有**；宽口径复核要放开
  「平均」前缀、全角斜杠 `／`、大小写等变体，确认「不是漏取」才能填「无」。

### 6.6 表头换版（v1 → v2 → v3 …）时的最小重做

用户会迭代表头。**先逐字段 diff 新旧表头**（`read_fields.py` 两次输出对比），只重做变化列：

```
多数列同名 → 逐值复用上一轮人工定稿（用脚本逐列比对确认无回归）
 少数列变化 → 只重跑这几列
```

实测三轮迭代（同一批 28 份）：

| 版本 | 字段数 | 需重做的列 | 机器用时 | 墙钟 |
|---|---|---|---|---|
| v1 | 32 | 32（首轮） | 85.8 s | — |
| v2 | 32 | 2 | 39.33 s | ≈39 min |
| v3 | 15 | 5 | **7.46 s** | **≈3 min 16 s** |
| v4 | 6 | 2（入院记录类型、主诉） | **7.9 s** | ≈5 min |
| v5 | 4 | **0（纯子集，直接投影）** | **6.8 s** | ≈1 min |

> v3 字段数砍半、看似改动很大，但 15 列里有 10 列与 v2 同名同口径 → 真正重做只有 5 列，机器只要 7.5 s。
> **换版成本取决于与上一版的交集，不取决于字段总数。**

**前提**：上一轮的中间产物必须保留 —— `results_*.json`（复用源）、`字段线索.txt`、`检验单列表.txt`、
`evidence_pack`，以及各版人工定稿映射（`v2_desc_*.json` / `v3_desc_*.json` / `v3_echo_time.json`）。
描述列的人工定稿一律放**独立 JSON**、按文件名注入，不要硬编码进代码。
组装器用「复用 + 定点替换」写法（见 `build_results_v3.py`，带 有/无 与描述的一致性自检）。

### 6.6.1 用户说「再次按表头提取」时，先确认表头到底变没变

用户会**同名原地改表头**（实测 `病历信息提取v5.xlsx` 在 17:32 与 17:36 两次读取内容不同）。
所以每次收到「请再次按表头提取」都必须先做三件事，再决定要不要重做：

```bash
stat -c '%y %s %n' "<字段模板.xlsx>"        # ① 看 mtime 是否晚于上一次读取
cp timing/fields_<上版>.json timing/_prev.json
"$PY" "$SKILL/scripts/read_fields.py" "<字段模板.xlsx>" > timing/fields_<本版>.json   # ② 重读
# ③ 逐字段 diff（同名文件也要 diff，不要靠文件名判断版本）
```

然后按 diff 结论分三档处理：

| diff 结论 | 处理 | 实测量级 |
|---|---|---|
| 字段集合/口径都没变，只是措辞 | **重新出表**即可（无需重判） | ≈7 s |
| 新表头是旧表头的**子集** | 用 `pick_fields.py` 直接投影 | ≈7 s |
| 有列的口径变了（如 v4 的入院记录类型） | 只重判那些列 | ≈8 s |

**换版不只是「换字段集」，列名文案也会变**（实测 `病历信息提取.xlsx` 在 2026-09-18 被换成
「32 字段全集 + 前几轮细化措辞」，第 3 列由「超声心动图…」改为「心脏超声的检查类型…」）。
组装结果时**必须按位置映射到新列名**再输出：

```python
vals = [src[src_keys[i+1]] for i in range(len(F))]      # 按位置取旧值
...  # 定点替换若干位置
rec = {"文档标题": name, **{F[i]: vals[i] for i in range(len(F))}}   # 套新列名
```

若沿用旧列名输出，`summarize.py` 会按新列名取不到列，**整列静默写空**（本次一次写空 9 列）。
交付前务必检查「结果表有无空列」+ 跑确定性自检；本次正是靠 `echo_type_scan.py --check` 抓到的。

**遇到 `PermissionError: [Errno 13]` 不要重试**：先看目标目录有没有 `~$<文件名>` 锁文件
（用户在 Office / 预览面板里打开着）。有锁就**输出到带后缀的新文件名**（如 `..._表头修正版.xlsx`），
并在交付说明里写明「关掉预览后可覆盖回原文件名」。

### 7. 汇总成表

先把每份结果重组为 dict（key **严格等于字段名**，缺失填「无」；每个 dict **必须含 `"文档标题"` 键**，
值 = 该病历 docx 文件名去扩展名，如 `703386 无胱抑素 李军`），收集成 dict 列表写入 `results.json`，
再：

```bash
# 一步到位（推荐）：自动读字段模板 → 拼列序 → 汇总
"$PY" "$SKILL/scripts/stage2_build.py" "<字段excel.xlsx>" "results.json" "<结果.xlsx>" "<列顺序.txt>"
# 等价分步：
"$PY" "$SKILL/scripts/summarize.py" "<results.json>" "<结果.xlsx>" --columns "文档标题,<字段1>,<字段2>,..."
```

**表格格式（确定性，必须遵守）**：
- 第一列固定「文档标题」，**值 = 病历 docx 文件名（去扩展名）**，与输出目录名一致（如
  `703386 无胱抑素 李军`、`703530 无胱抑素 李雪飞`）；后面严格按用户 excel 表头顺序。
- **每行一个病人**（行式），一份 docx 一行，不得转置成列式。
- 列数 = 表头字段数 + 1，不合并/不增删列。

### 8. 规则检查

读 `references/rules/RULES_INDEX.md` → 逐条读 `references/rules/<ID>.md` → 核对结果表 → 输出报告：

| 规则 | 严重级 | 判定 |
|---|---|---|
| REQ001 | warning | 提取结果为 `无`/空/`信息不足` 的字段 → 列出行与字段名 |
| FMT001 | warning | 字段名含「日期/时间」且非空时须匹配 `\d{4}-\d{2}-\d{2}` |
| PRV001 | error | 脱敏文本/结果表中不得残留已识别的姓名/医院名明文（回退补掩码） |

报告格式：`规则ID | 严重级 | 是否通过 | 异常项 + 原文片段`。
规则检查是**确定性判定**，不依赖 LLM；有 error 级异常必须明确告知，不得静默吞掉。

## 大批量（≥10 份）工作流

2026-09-17 实跑 28 份（同院同期、511 张图、87.6 MB，输出根 `output/`）沉淀出以下流程与脚本。

### 0. 先探路：可访问性 + 规模 + 病历名取名

```bash
"$PY" "$SKILL/scripts/list_docs.py" <docx路径清单txt> timing/<批次>_files.tsv   # 存在性/字节数
```

再用 `patient_name_from_filepath` 预演一遍取名（见下「病历名坑位」）。
按图片数估 S1 耗时：**≈9~10 s/图**（MinerU 解析 + rapidocr 补全），据此决定是否分批。

### 1. S1 批量图转文 + 补全（`batch_supplement.py`）

```bash
"$PY" "$SKILL/scripts/batch_supplement.py" <docx清单txt> <输出根目录> --log timing/<批次>_s1.tsv
```

- 逐份输出 `output/<病历名>/`；**已有 `<病历名>_补全.md` 且非空 → 跳过**（天然支持断点续跑）
- 单份失败记 `FAILED` 后继续（铁律 4），日志含每份秒数，结束打印 成功/失败/跳过/总耗时
- 必须放**后台**跑，且只保留一份并发（MinerU 单实例，串行最快也最稳）

### 2. 复用「跨病历共用词表」（同院批次的关键提速点）

同院医护高度重叠，把上一批的 `敏感词清单.txt` 沉淀成共用词表，新批次直接喂 `--manual`：

```bash
"$PY" "$SKILL/scripts/build_shared_manual.py" <上一批各份敏感词清单.txt...> timing/shared_manual_<批次>.txt \
    --drop "<上一批患者名,及其名部,单字词...>"
```

- **必剔三类**：① 纯数字（住院号/床号/流水号，每份不同）② 上一批**患者姓名及其名部**
  （跨病人复用无意义，撞词会误掩）③ **单字词**（OCR 截断残留，误伤面太大）
- 实测：5 份 → 135 个共用词（医护/医院/地址类），28 份新批次一次命中大部分医护名

### 3. S2–S5 批量（`batch_stage2.py`）

```bash
"$PY" "$SKILL/scripts/batch_stage2.py" <病历名清单txt> <输出根目录> <共用词表txt> <日志tsv>
```

逐份串起 9 步并计时：S2a 识别 → S2b 名部安全网 → S2c 合并（专有词_人工 + 共用词 + 名部）
→ S2d 终词表 → S3 掩码 → S4a 复扫 → S4b 残片 → S5 转 docx → S2e 可读副本；
结束打印各阶段「份数/合计秒/中位秒」。**单份专有漏名**写到该份目录的 `专有词_人工.txt` 后重跑本脚本即可。

### 4. 图片层复核按需降级（`image_scan.py --strip`）

511 张整图 2x 全量 OCR 约 40 min。同院同 EHR 系统时标题栏位置固定，
可只 OCR 顶部条带（`--strip 0.08`），提速约 10 倍；**换院/换系统必须回到整图**。

### 病历名坑位（2026-09-17 修）

`patient_name_from_filepath` 原实现取「最后一个中文段」，遇到本批命名会取错：

| 文件名 | 旧行为 | 现行为 |
|---|---|---|
| `602961 无胱抑素 郭斯光 第二次入院.md` | 取「第二次入院」❌ | 剔除「第N次入院」段 → **郭斯光** ✅ |
| `584261 无心电图记录.md` | 取不到 → None | 仍 None，但 `run_code_engine` **回退到正文 `姓名：` 锚点高频项** ✅ |
| `703386 无胱抑素 李军_补全.md` | 李军 ✅ | 李军 ✅（不回归） |

实现要点：`_FILE_STEM_NONNAME` 段黑名单 + `re.search(r"入院|出院|记录|无胱抑素|无肌酐", s)` 整段剔除
+ `2 <= len(s) <= 4` 长度约束；回退路径在 `run_code_engine` 里，stats 行会显示「(正文回退)」。

### 零图片病历（`X 无心电图记录.docx`）

本批 2 份「无心电图记录」docx 只有 §1 KB，`word/media/` 条目为 **0**，
`document.xml` 仅 20 字（`心脏彩超入院记录出院记录病程记录检验报告` 这 5 个栏目名）——
即**导出时该病人无任何截图内容**。这类文件不要当失败处理：`supplement.py` 会正常产出（内容近空），
但**必须在交付说明里显式列出**，避免被当成「处理成功但数据为空」。

## 计时规范（用户会要「每个环节的用时」）

1. **所有确定性环节一律用 `stage_timer.py` 包裹**，计时落盘到 `timing/<YYYY-MM-DD>_stages.json`，
   不要凭记忆估。示例：
   `"$PY" scripts/stage_timer.py "S3 掩码脱敏 [<病历名>]" -- "$PY" "$SKILL/scripts/mask.py" ...`
2. **S1（MinerU+补全）与 S1b（整图复核）用后台任务自身耗时**，并从日志时间戳推算逐份耗时
   （rapidocr 引擎初始化行的时间戳即为该份 `[3/4]` 起点）。
3. **S6 逐份提取**无脚本可挂，用墙钟：记录「字段线索产出时刻 → results.json 落盘时刻」。
4. 交付时同时给出 **机器耗时**与**人工判定耗时**（敏感词补词、字段核对），二者量级差 100 倍以上，
   混在一起报会误导。
5. 已实测基线（2026-09-17，5 份 / 113 图 / 24.9 万字符）：S1 18m01s、S1b 8m42s、
   S2 2.5s、S3 2.2s、S4 4.5s、S5 3.0s、S6 6m48s、S7 2.8s、S8 1.2s；
   端到端墙钟 ≈1h58m（含 S2 人工补词 ≈12 min）。

## 铁律

1. **只增不减**：补全不覆盖 MinerU 已识别内容。
2. **独立输出目录 + 命名一致**：每份 docx 用 `output/<病历名>/`（病历名 = docx 文件名去扩展名，
   如 `output/703386 无胱抑素 李军/`）；产物文件名前缀一律用病历名，禁止自拟简称；
   开始前确认目录不存在或为空，**禁止读取/复用历史任务的产物**。
3. **不覆盖已有文件**：输出目录中同名既有文件会被跳过。
4. **失败退回**：任一图补全失败 → 退回该图原始内容，不中断整体任务。
5. **先脱敏再提取**：阶段二绝不用未脱敏文本。
6. **数据不外传**：rapidocr 本地推理（0 网络）；脱敏默认代码引擎 0 网络；MinerU / Ollama 备份引擎均在内网（10.20.79.38）。
7. **阶段一结束必须停下**，等用户确认后再进入阶段二。
8. **不改动其他技能**：本技能自包含。
9. **规则判定字段先判后填**：字段名里嵌了判定规则的（如「心衰情况」「房性心率失常」「是否疑似心衰」
   「高血压/糖尿病证据优先等级」），必须逐条对照规则原文走分支，不得凭临床直觉填。
   遇到规则未覆盖的分支（例：入院诊断无心衰、出院诊断有心衰，但入院记录里没有
   「补充诊断 急性心力衰竭」→ 规则 2 的 a/b 两种情况都不成立），按 b 填「否」，
   **并在交付说明里显式指出该处判定存在规则空白**，让用户复核。
10. **原文缺失就填「无」，禁止推算**：如「出院日期」原文只有「入院时间 + 住院天数：8 天」
    而没有出院时间时，填「无」，并在报告里给出可得的证据（住院天数、末次病程日期），
    由用户决定是否推算，不要擅自把推算值写进结果表。
11. **同一指标多次出现时锚定同一份报告**：EF/E/e'/检查时间必须来自同一份超声报告；
    检验值必须与其 `申请时间` 配对（结果表 ↔ 单据行按申请时间对齐）。
12. **表头换版只重做变化列**：先 diff 新旧表头，变化的列才重跑并重新人工定稿，其余列逐值复用；
    人工定稿产物（如描述列映射）放独立 JSON，不写死在代码里（见 6.6）。
13. **描述列必须与判定列自洽**：判「有」就不能留空描述，判「无」的描述必须是否定句；
    来源不在表头列举范围内时（如病程记录、会诊意见），可在描述里注明来源，
    但**是否改判要在交付说明里显式列出**，由用户定口径。
14. **描述列要求「只输出最高优先级来源」时不得并列**：表头写了
    「若同时存在于若干个不同优先级项目，只输出最高优先级项目中的相关内容」时，
    一个格子里只能有一个来源；舍弃的低优先级内容（如现病史里的血压数值）若可能有价值，
    在交付说明里单独说明，不要塞回单元格。
19. **禁止硬编码字面量匹配取值**：不得写 `"值" if "指标名=值" in text else "无"` 这类一次性字面量判断；
    必须写成「指标名 + 容错分隔 + 数值」的正则，并先做实体解码与 HTML 标签压平（见 6.5.3）。
    取不到时先怀疑 `&#x27;` 实体与 `</td>` 切断，再怀疑原文缺失。
20. **能确定性重算的列，换版交付前一律重算并比对**：超声检查类型、入院记录类型、主诉、检验申请时间
    这类「可由原文确定性推导」的列，**不要只依赖首轮的人工定稿值**（换版只重做差异列，错误会被静默继承）。
    每次交付前跑一次 `echo_type_scan.py --check` 之类的自检；不一致就修基准结果再重新投影
    （本次实测抓到 2 处继承错误）。
17. **人工 OVERRIDE 必须留「重算触发条件」注释**：写进 OVERRIDE/定稿 JSON 的每个值，
    都要标注它由什么规则推导（如「检查所见 含床旁 → 床旁心脏」），否则下一版无法判断该值是否已经过期。
18. **时间列标了「精确到时分秒」就必须回源取全**：先找 `检查日期：` 完整时间，再退 `申请时间`；
    该院 OCR 会把日期与时间粘连（`2025-09-0514.55:45`）、用句点代替冒号（`14.55:45`）、
    丢掉日期首位（`025-08-11`），都要归一化。原文真的只有 `00:00` 时按原文填并列为待复核，
    **不得推算、不得留空**（见 6.5.1）。
