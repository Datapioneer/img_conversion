## 6. 逐份提取——工程做法

- **字段名不要手打**：字段表里存在「含中文引号、逗号、内嵌换行」的超长字段名（本次最长一条 300+ 字）。
  先用 `read_fields.py` 的输出生成 `fields_prompt.txt`（逐字字段名 + 判定要点），让提取方直接读该文件，
  避免转写错误导致字段对不上。
- **两种打法**：
  - 单会话逐份：给出 `fields_prompt.txt` + 该份脱敏全文。
  - 子代理并行：一份病历一个子代理，各自读 `fields_prompt.txt` 与自己的 `_脱敏.md`，
    并要求把结果 JSON **落盘**到 `output/<病历名>/<病历名>_提取.json`——落盘比看返回值可靠。
- **耗时随字符数近线性**：3.3 万字符 ≈ 37 s；6.5 万字符 ≈ 238 s。串行 5 份 700 s；
  并行理论上限 ≈ 最慢一份（本次因逐个派发未吃到并行收益，串行跨度 892 s）。
- **⛔ 汇总前必须归一化 key**：模型返回的 key 常把**真实换行写成字面量两字符 `\` + `n`**，
  而字段表里是真实换行，直接 `dict.get()` 会全部落到默认值（**症状：缺字段 = 多字段 = 同一批**）。
  汇总前统一 `k.replace("\\n", "\n")`，并断言「缺字段 = 0 且 多字段 = 0」。

## 6b. 复核——必须落到「来源」上（本轮最有价值的一步）

带「仅从位于 `<table> ... </table>` 标签内部获取相关信息」的字段，**不能只看数值是否存在**，
要确认「指标名 + 数值」是否真的成对出现在**表格行**里：

- 同一指标常在**病程记录 / 出院记录 / 诊疗经过 / 抢救记录**的叙述文字里重复出现，
  而这些叙述在 OCR 结果里也常常被包在 `<table>` 标签里（EHR 页面本身就是表格），
  于是「表内」这个机械判据会被轻易满足 → **必须再确认它落在「项目 / 结果值」这种键值行上**。
- 实测反例：某份病历首次 NT-proBNP 的检验单报告表格行缺失，实测值 `>35000.00 pg/ml` 只出现在
  病程记录/出院记录叙述中 → 按来源限定应填「无」，而不是 35000。
  这类情形必须**在报告里显式提示用户**，否则用户会以为流水线丢数据。
- 判据脚本：把候选数值/字符串在原文中定位 → 检查其是否落在 `<table>...</table>` 区间内
  **且**同一行存在「项目名 / 结果值」这类键值对。
- 同理核对**申请时间 ↔ 检验时间**是否对齐同一张检验单报告：同一天可能存在多张同类申请单
  （实测钟广章 2025-04-28 有 17:12:07 与 17:22:15 两单），应取与 docx 内**可见检验单报告**
  （检验时间对齐）的那一单。

## 8. 规则检查——实现与口径

本仓库已实现确定性检查脚本 `scripts/check_rules.py`（REQ001 / FMT001 / PRV001，不依赖 LLM），
用法：

```bash
"$PY" scripts/check_rules.py "<结果.xlsx>" "<输出目录>" \
  --manifest "<文档标题>=<该份敏感词清单.txt>" ...
```

- REQ001：值为 `无`/空/`信息不足` → warning
- FMT001：字段名含「日期/时间」且值非空 → 须含 `\d{4}-\d{2}-\d{2}`
- PRV001：结果表字段值中残留该病人已识别的姓名/医院名明文 → **error**（退出码 1）

**口径提示**：REQ001 把**所有**「无」都计入异常，但很多字段的值域本身就以「无」为合法值
（如「平均E/e'…若无则填：无」「高血压…只填有/无」「胱抑素测值」）。
实测 46 项 warning 中相当比例是预期值。建议字段表增加「空值是否算异常」开关，
或把「无」区分为「显式无（合规）」与「缺失（异常）」。

## 为什么「逐份提取」这么贵（2026-09-16 带打点实测）

### 根因：Read 工具**单行 2000 字符静默截断**

病历 md 的表格行（`<table>...` 整行）长达 4649~7831 字符，被 Read 截掉尾部后：

| 文档 | 字符 | 最长行 | >2000 字符行数 | 被截断丢失字符 | 占全文 |
|---|---|---|---|---|---|
| 703530 无胱抑素 李雪飞 | 64584 | 7831 | 8 | 12816 | 20% |
| 703543 无胱抑素 邢云 | 73309 | 7294 | 11 | 21767 | 30% |
| 703641 无胱抑素 陈川新 | 50193 | 4644 | 7 | 8317 | 17% |
| 703386 无胱抑素 李军 | 33033 | 5131 | 5 | 5940 | 18% |
| 钟广章 | 31357 | 4649 | 5 | 6050 | 19% |

提取方**看不见这些内容**，只能再用 Grep / Bash 分段回读 → 多轮串行工具往返。

### 单份耗时分解（钟广章，打点实测）

| 子环节 | 未重排换行 | 读 `_可读.md`（重排后） | 本质 |
|---|---|---|---|
| 读字段清单 | 3.9 s | 13.4 s | 1 次 Read 往返（含模型生成 tool call） |
| 第一遍通读全文 | 3.8 s | 9.5 s | 1 次 Read |
| **补看被截断的超长行** | **22.0 s**（2 Grep + 4 Bash） | **0 次额外调用** | 6 次额外往返 → 0 |
| 33 字段提取推理 | 5.3 s | 38.9 s | 纯生成，**方差最大（7 倍）** |
| JSON 落盘 | 6.5 s | 10.0 s | 1 次 Write（往返成本 > 读同尺寸文件） |
| **合计** | **41.5 s** | **78.5 s** | |

> A/B 说明：两组是不同子代理、单次运行，**推理环节方差极大（5.3 vs 38.9 s）**，
> 所以总耗时没有直接下降。但「补看往返次数 6 → 0」是**确定的结构性收益**。
> 结论：S2.2 耗时 ≈ 「串行工具往返次数 × 单次往返固定延迟」+「当次推理深度（方差大）」，
> **不是被文档字节数主导**。这解释了 5 份 37~238 s 的 6.4 倍差：截断行越多、图越多 → 往返越多。

### 优化清单（按收益排序）

1. **提取前先重排换行**（本仓库已实现 `scripts/unwrap_md.py`）：生成 `_可读.md`，
   只在 `</td>` `</tr>` `</table>` 与中文标点处插入换行，最长行压到 ≤1800，
   **逐字符守恒**（去掉换行后逐字符相同），一次 Read 读完，补看环节归零。
   原 `_脱敏.md` 不动，`_可读.md` 仅作阅读副本。
   ```bash
   "$PY" scripts/unwrap_md.py "output/<病历名>/<病历名>_脱敏.md" "output/<病历名>/<病历名>_可读.md"
   ```
2. **5 份并行派发**：串行 700 s → 理论上限 ≈ 最慢一份（~240 s）。
3. **子代理只落盘、不回传完整 JSON**：baseline 每组把 33 字段全文打在回复里，
   额外产生数千 token 输出；改为「落盘 + 只回一行耗时打点」可省一次长输出。
4. **把来源校验脚本化**（表内/表外、申请时间↔检验时间对齐）→ 减少必须让模型补看的情形。

### 接入方式（阶段二新增前置步骤 S2.2a）

```
阶段二启动
 ├─ S2.1  read_fields.py                → 33 字段清单
 ├─ S2.2a unwrap_md.py          【新增】
 │        output/<病历名>/<病历名>_脱敏.md  →  <病历名>_可读.md
 ├─ S2.2b 逐份提取：读 <病历名>_可读.md（不再读 _脱敏.md）
 ├─ S2.3  summarize.py                  → 结果.xlsx
 └─ S2.4  规则检查
```

```bash
"$PY" scripts/unwrap_md.py "output/<病历名>/<病历名>_脱敏.md" "output/<病历名>/<病历名>_可读.md"
# 默认 --limit 1800 --lookback-max 400 --ratio 0.6 --guard 100
# 退出码：0 通过 / 1 守恒失败 / 2 行长超限 / 3 标签被切断 / 4 参数非法
```

**接线四原则**：
1. **每次重建**，不复用旧副本（幂等、单份 ~1.5 s；避免 `_脱敏.md` 补掩码重跑后副本陈旧）
2. 硬红线失败 → **该份回退读 `_脱敏.md`**（退化为原来的补看路径）并告警，**不中断阶段二**（与铁律 4 一致）
3. 真值锚定不变：results.json 的 `文档标题`、行序、规则检查、xlsx 列全部仍锚定病历名与 `_脱敏.md`
4. **`_可读.md` 绝不喂给 `md2docx.py`**（插入的换行会在转 docx 时产生多余断行）；正式交付物始终是 `_脱敏.md`

### 红线（8 条）

R1 去掉换行后逐字符相同（违反→退 1）｜R2 原文件不动｜R3 每段 ≤1800（→退 2）
R4 换行不落在 HTML 标签内部（→退 3）｜R5 表格行切点在 `</td>|</tr>|</table>|</p>` 之后
R6 文本行切点在 `。！？` 之后（**尽力**）｜R7 管道表格行整体不切（WARNING）
**R8 冲突时 R3 优先**（段长上限是目的本身，R5/R6 让位并记 WARNING）

### 算法（三级降级）

窗口 = `[pos + 0.6×limit, pos + limit]`
L1 窗口内取**最后一个**断点（按车道选断点集）→ L2 没有则**向左扩展 ≤400 字符**重找
→ L3 仍没有则硬切到 limit，并用 `</?[A-Za-z][^<>]*$` 守卫把切点前移到标签之前

车道分流：`"<table>" in line` ⇒ 表格车道（结构断点）；否则文本车道（`。！？`）。

> **关键认知**：`Read` 的 2000 字符上限是按**物理行**算的，而 MinerU 把整张表序列化在一个物理行里
> （本语料 4644~7831 字符/行，占全文 71%~82% 字符量）。所以超长行 = 表格行，100% 命中信息密度最高的检验单/病程/出院记录。

### 提取回归的归因方法（重要方法论）

6 次提取（A×3 读 `_脱敏`、B×3 读 `_可读`）与基准比对，出现 1~4 个字段差异。
**判定「是否 reflow 引起」的方法：比较组内差异 vs 跨组差异。**

| 比较 | 33 字段中不一致字段数（均值） |
|---|---|
| A 组内部（同一输入） | **2.67** |
| A–B 跨组 | 1.78 |
| B 组内部（同一输入） | **1.33** |

**同输入组内差异 > 跨组差异** ⇒ 差异来自模型随机性，与 reflow 无关；且重排后自洽性更好。
差异内容也全是良性：掩码字符数转录噪声、`1.` 序号前缀有无、OCR 错字是否被自动纠错、已知的同日多单歧义。

> **教训**：做这类 A/B 时，**"与一次基准比对"是不充分的**——必须做组内对照，否则会把模型随机性误判成修复引入的回归。

### 顺带发现的质检项

1. `病人ID和姓名` 字段含 `█` 掩码时**转录不稳定**（6/6 跑不一致）→ 建议从文件名确定性生成，或先归一化 `█+` 再比对。
2. 源数据有 **OCR 截断残留**（行尾孤立 `>`，如 `…N-末端脑利钠肽前体>`）→ 可加质检规则：行尾裸 `<`/`>` ⇒ 疑似截断。
3. 同日多张同类申请单（钟广章 2025-04-28 的 `17:12:07` 与 `17:22:15`）→ 需人工裁决规则。
