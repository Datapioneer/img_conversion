# 结构化提取子技能

## 步骤

1. 读「提取字段 excel」（单行表头，每格一个字段名，如 性别/年龄/诊断）：
   ```bash
   python references/extract/scripts/read_fields.py <字段excel>
   ```
   得到 `{"fields": [{"name","mode","judge","required"}, ...]}`（单行表头时 mode 默认 `exact`）。

2. 对每份「已脱敏文本」，**由 WorkBuddy 用当前选中的模型（右下角）**逐份提取，不要走 MCP 线上接口。若用户需要**限定指标只取某个来源**（例如"只取检验报告表格里的值，不取叙述文字里出现的同名指标"），把下列 `<来源限定说明>` 追加进提示词（见步骤 2 提示词模板末尾）。固定提取提示词如下（`<字段>` 用上一步 `read_fields.py` 返回的字段名，`<脱敏文本>` 用该文档的脱敏全文）：
   ```
   下面这段文字来自患者病例的图片文字识别结果。请严谨处理病历信息，执行以下任务：
   针对文本进行绝对提取，精准提取以下特定内容的值：
   - <字段1>
   - <字段2>
   ...
   输出严格按照如下 python 字典格式返回，不要有任何额外的前后缀或 Markdown 代码块包裹标记；每个字段必须独立成一个键，严格使用给定字段名，不得合并字段、不得遗漏字段、不得更改字段名：
   {
       "<字段1>": "[精准提取的内容，如果无则填'无']",
       "<字段2>": "[精准提取的内容，如果无则填'无']"
   }
   <来源限定说明（可选，仅当用户要求只取某来源时追加，示例见"示例：只取表格值"一栏）>
   病历信息：
   <脱敏文本>
   ```

   把返回结果解析成 dict，缺失字段补 `无`。单行表头默认 `exact`；旧版多列模板才区分 exact/fuzzy_query/fuzzy_judge（此处按 exact 处理）。

   ### 示例：只取表格里的指标值（用户明确要求时）

   输入文本是 MinerU 图转文产物，指标可能**同时**出现两类位置：
   - **表格/排布文本**：被 `<table>...<tr>...<td rowspan=1 colspan=1>指标</td>...` 包裹，如化验/检验报告表头+数据、数值矩阵、信息栏。
   - **叙述段落**：现病史/既往史/病程描述里顺带提到的同名指标。

   当用户要求"只取表格中的指标"时，把下面这段话加进提示词（放在"病历信息："之前），帮助模型判断：

   ```
   注意来源限定：目标字段的值，仅从位于 <table> ... </table> 标签内部的
   "指标名 <td> 数值" 对应关系中提取；若某指标只出现在叙述式段落（现病史、
   既往史、病程描述、医嘱文本等普通文字）中而未出现在任何 <table> 内，
   则该字段填"无"，不要从叙述文字里取值。若同一指标在多个 <table> 内出现，
   取检验报告部分（通常紧跟"检验人/样本/结果/参考区间"等表头）那一处。
   判断依据是原义所在的 HTML 表格结构，不是关键词重复。
   ```

   要点（写给提取模型的结构知识，可并入提示词）：
   - 表格值通常是 `<td rowspan=1 colspan=1>指标名</td>` 后面紧跟 `<td rowspan=1 colspan=1>数值</td>`
     或表头行后对应同一 `<tr>` 的数值列，取与该指标同行的数值单元格。
   - 数值单元格两侧可能粘连（如 `2025-02-1108:23:20`），用已知指标语义纠偏，不当作新字段。
   - 只在用户明确要"只取表格值"时加来源限定；默认提示词不限定来源、照常全部提取。

3. 汇总所有 docx 的结果成一张表：
   - 对每个 docx，用「文档标题 + 用户表头字段」重组为一个 dict：key 严格等于字段名，缺失填"无"（不要直接用 LLM 返回的原始 dict，防止字段名不一致/被合并/被转置）。
   - 收集成 **dict 列表**（每行一个病人，不要转置成列式），写入 `results.json`。
   - 汇总时用 `--columns` 固定列顺序：
     ```bash
     python references/extract/scripts/summarize.py <results.json> <结果.xlsx> \
       --columns "文档标题,<字段1>,<字段2>,..."
     ```

## 结果表格格式（确定性，必须遵守）

| 文档标题 | 字段1 | 字段2 | ... |
|---|---|---|---|
| 张三.docx | ... | ... | ... |

- 第一列固定是「文档标题」（docx 文件名），后面严格按用户 excel 表头字段顺序。
- **每行一个病人**（行式），不得转置成列式。
- **列数 = 表头字段数 + 1（文档标题列）**，不得合并列、不得增删列。

## 注意事项

- 提取由 WorkBuddy 当前模型完成，换模型/提供商在右下角模型选择器切换；不再依赖 `llm-mcp` 的 DeepSeek 直连。
- 只对**已脱敏**文本做提取，不要拿原始 Markdown。
- 字段 excel 是单行表头；若用户给的是旧版多列模板（含"字段名"列），read_fields.py 也会兼容。
- 字段为空时，交给 rule-check 提示（REQ001，warning 级）。
