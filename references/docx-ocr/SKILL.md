# 图转文子技能

## 步骤

1. 先把 docx 复制到本地工作目录 `output/<文档名>/<文档名>.docx`（避开网络盘 UNC 路径）。
2. 用固定直连库图转文（**不要**用会话内 MCP 工具，其约 2 分钟超时撑不住整份病历）：
   ```bash
   python "<skill 的 mcp_client 目录>/mineru_call.py" \
       "<宿主机docx绝对路径>" "<output/<文档名>/<文档名>_图转文.md>"
   ```
   - 脚本内部自动把宿主机路径 `E:\shiny_wd\...` 转成容器内 `/ws/...`（根映射 `E:\shiny_wd` → `/ws`，见 `mcp_client.py` 的 `to_container_path`），因此只需传宿主机路径。
   - 长超时默认 1800s，足以覆盖整份病历 OCR。
3. 返回的 Markdown 已按「每张图片一个一级标题(`# 图片 N`)」组织。
4. 将 Markdown 原样写入工作目录（如 `output/<文档名>/<文档名>_图转文.md`），供后续脱敏/下载。

## 注意事项

- 空文档/无图片的纯文本 docx：工具会走整份文档解析，仍返回 Markdown。
- 单个图片解析失败时，工具会返回 `*(图片 xxx 解析失败)*` 占位，不要中断整条任务。
- 图转文耗时较长，不要重复调用同一份文档。

## MinerU 输出里的 `<table><tr><td rowspan=1 colspan=1>…</table>` 格式（常见，勿当异常）

MinerU 后端的 Markdown 会把「按行/按格排布的文本」用 HTML 表格标签包裹呈现行列关系，会产生两类 table：

1. 带引号 `<td rowspan="4" colspan="2">`：真正的结构化表格（有合并单元格），比重低。
2. **不带引号、每格固定 `<td rowspan=1 colspan=1>`、`<table><tr>` 无换行挤成一行**：这是最常出现的"奇怪格式"，本质是**用表格标签表示的排布文本**，并不是真正的表格。典型出现在：
   - 患者信息栏/基本信息（姓名/性别/年龄/出生地/常住地址…）
   - 化验/检验报告的表头行（单据/样本/检验人/申请人/时间…）与下方数据
   - 数值矩阵、指标对照表、医嘱列表
   - 每一格就是原图里一个独立的"词/字段"，`rowspan=1 colspan=1` 恒为 1，无合并语义。

**原因**：不是脚本 bug，`mcp_client/mineru_call.py` 只是把 `parse_document` 返回值原样写盘。这是 MinerU 结构化输出的正常表现。

**处理建议**：
- 图转文中间产物里保留原样即可，无需清洗（脱敏掩码会按文本内容处理，不依赖这些标签）。
- 若后续要把 table 真正转成 Markdown 表格，可对第 2 类固定格式做正则规整：把连续 `<tr>…</tr>` 重组为 `| 单元格 |` 形式，但要小心「一个 `<td>` 内含多行/多词」的情况（如住址整段挤在一个格子里），不要粗暴按行切分，否则会破坏内容。
- data 在 mask.py 中按纯文本关键词匹配时不受影响。
