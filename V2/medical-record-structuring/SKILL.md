两阶段推进：**阶段一**产出图转文/补全/脱敏产物；**阶段二**按用户提供的字段 excel 做提取与规则检查。

## 阶段一：图转文 + 补全 + 脱敏

### 1. 图转文 + 本地增量补全

```bash
PY="C:/Users/dongyi.qiu/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
SKILL="<本技能目录>"
"$PY" "$SKILL/scripts/supplement.py" "<docx绝对路径>" "<输出目录>" [--debug]
```

产出三件：
| 文件 | 说明 |
|---|---|
| `<名称>_图转文.md` | MinerU 原始结果（对照用） |
| `<名称>_补全.md` | **补全后的最终产物**（补入内容有 `<!-- 本地 OCR 补充识别 -->` 标注） |
| `<名称>_补全报告.txt` | 审计：逐图判定与补入明细 |

**补全机制**（详见脚本头注释）：
- **粗筛**：该图 md 缺「正文锚点」（检查所见/报告结果/备注/检查日期/超声测值）→ 需补。
  （"检查项目/申请时间/检查人"属面板字段，**不作判据**）
- **本地 OCR**：rapidocr 全图识别，2x 放大；坐标换算回原图系。
- **四重过滤**：① 行级 n-gram 覆盖率 ≤0.5 ② box 中心 x > 图宽×0.5 ③ 锚点 y 带界定正文区
  ④ 噪音正则（纯数字/日期/本机IP/服务器/医院系统名）。
- **只增不减**：MinerU 已识别内容一字不动；正常图（锚点齐全）直接跳过。

> **实测坑位：医院名可能只存在于图片层。** EHR 截图的**窗口标题栏**（形如
> `XX医科大学第二附属医院-医技工作站`）既不被 MinerU 转成文本，也不在补全的采纳区内
> （补全只取右侧正文区 `x > 图宽×0.5`），因此 LLM 无从识别、文本层也永远不含该词。
> 阶段一结束后建议补一步**整图**复核：对 docx 内嵌图做整图 rapidocr，用
> `医院|医科|附属|卫生|保健` 扫一遍；命中词并入 `--manual` 词表
> （即使文本层不含该词，掩码是空操作，但会记入敏感词清单，可据此向用户说明
> "医院名仅在截图标题栏，文本交付物不含，如需遮盖请另行处理图片层"）。

### 2. 敏感词识别

```bash
"$PY" "$SKILL/scripts/sensitive.py" "<_补全.md>" "<敏感词.txt>" [--manual "<手动词.txt>"]
```

- 三段合并：① 正则自动提取（床号/住院号/手机号/ID/地址）② 分块调 Ollama qwen3:32b
  识别医院名/人名 ③ `--manual` 手工补齐词（每行一个）。
- 分块：优先按 `# 图片 N`，否则按 8000 字/块；单块失败重试 1 次后**中止**（防漏识别）。
- 提示词中示例医院/人名偶被模型照抄返回，属已知无害现象（多余词匹配不到正文）。
- **多次住院病历**：每个住院号的床号/流水号都不同，且常以「数字+床」「(流水号」无标签格式出现，
  务必手工补齐后用 `\d{3,6}床`、`\(\d{5,9}` 在脱敏文件上扫一遍再重跑掩码。
  （注：本技能的正则**已内置** `数字+床`、`(数字)` 两种无标签格式，实测可多抓若干条。）

**Ollama 不可用时的降级**：
- 若报 `cudaMalloc failed: out of memory`（qwen3:32b 约需 19.7GB 显存），说明该机器显存被占用
  （例如刚跑完 MinerU）或不足。可：① 稍后重试；② `--model` 换更小模型；
  ③ 用 `--no-llm` 跳过 LLM，**仅用正则 + 手动词**（此时务必用 `--manual` 补齐所有医院名/人名，
  否则 PRV001 会不通过）。
- `--no-llm` 只做确定性提取，不调任何模型。
- **降级后必须核对词数，不要只看"完成"字样（实测坑）**：`sensitive.py` 里 `num_ctx` 硬编码为 16384。
  现场遇到 32b 报 `cudaMalloc failed`（约需 19.7GB），换 `qwen3:14b` 后**全过程无报错、但返回 0 词**
  （小显存下大 KV cache 申请失败导致输出为空）。此时改用小上下文（`num_ctx=8192`）直连复测即可正常
  识别出人名。两个结论：① 换模型后一定要逐条核对人名是否齐全，必要时把姓名也写进 `--manual`；
  ② LLM 输出有随机性（同一份文档两次运行，一次 9 人全中、一次只出 6 人且漏掉患者姓名），
  **凡是能从正文肉眼确认的姓名/编号，全部固化进 `--manual`，把结果变成确定性的**。

### 3. 掩码脱敏

```bash
"$PY" "$SKILL/scripts/mask.py" "<_补全.md>" "<敏感词.txt>" "<_脱敏.md>" "<敏感词清单.txt>"
```

- 等长 `█` 掩码；长词优先；词内允许夹空白（容错）。
- 掩码由脚本完成，**不要手改**。漏识别时把补入 `敏感词.txt` 后重跑本步即可。

### 4. （可选）脱敏 md 转 docx

```bash
"$PY" "$SKILL/scripts/md2docx.py" "<_脱敏.md>" "<_脱敏.docx>"
```

输出三个产物并**询问用户**是否继续：
① 图转文/补全 Markdown ② 敏感词清单 ③ 脱敏全文。
**不要自动进入阶段二**——需等用户确认并提供「提取字段 excel」。

## 阶段二：结构化提取 + 规则检查

### 5. 读提取字段

```bash
"$PY" "$SKILL/scripts/read_fields.py" "<字段excel.xlsx|csv>"
```

返回 `{"fields":[{"name","mode","judge","required"}, ...]}`（单行表头时 mode 默认 `exact`）。

### 6. 逐份提取（由当前对话模型完成，不走脚本）

对每份**已脱敏文本**，用以下固定提示词（`<字段>` 取自上一步，`<脱敏文本>` 用该文档脱敏全文）：

```
下面这段文字来自患者病例的图片文字识别结果。请严谨处理病历信息，执行以下任务：
针对文本进行绝对提取，精准提取以下特定内容的值：
- <字段1>
- <字段2>
...
输出严格按照如下 python 字典格式返回，不要有任何额外的前后缀或 Markdown 代码块包裹标记；每个字段必须独立成一个键，严格使用给定字段名，不得合并字段、不得遗漏字段、不得更改字段名：
{
    "<字段1>": "[精准提取的内容，如果无则填'无']",
    "<字段2>": "[精准提取的内容，如果无则填'无']"
}
<来源限定说明（可选，仅当用户要求只取某来源时追加）>
病历信息：
<脱敏文本>
```

**来源限定（仅当用户明确要求"只取表格里的指标"时追加）**：

```
注意来源限定：目标字段的值，仅从位于 <table> ... </table> 标签内部的
"指标名 <td> 数值" 对应关系中提取；若某指标只出现在叙述式段落（现病史、
既往史、病程描述、医嘱文本等普通文字）中而未出现在任何 <table> 内，
则该字段填"无"，不要从叙述文字里取值。
```

- 解析返回为 dict，缺失字段补 `无`。
- **只对已脱敏文本提取**，不要用原始 Markdown。

### 7. 汇总成表

先把每份结果重组为 dict（key **严格等于字段名**，缺失填「无」），收集成 dict 列表写入 `results.json`，
再：

```bash
"$PY" "$SKILL/scripts/summarize.py" "<results.json>" "<结果.xlsx>" --columns "文档标题,<字段1>,<字段2>,..."
```

**表格格式（确定性，必须遵守）**：
- 第一列固定「文档标题」（docx 文件名），后面严格按用户 excel 表头顺序。
- **每行一个病人**（行式），不得转置成列式。
- 列数 = 表头字段数 + 1，不合并/不增删列。

### 8. 规则检查

读 `references/rules/RULES_INDEX.md` → 逐条读 `references/rules/<ID>.md` → 核对结果表 → 输出报告：

| 规则 | 严重级 | 判定 |
|---|---|---|
| REQ001 | warning | 提取结果为 `无`/空/`信息不足` 的字段 → 列出行与字段名 |
| FMT001 | warning | 字段名含「日期/时间」且非空时须匹配 `\d{4}-\d{2}-\d{2}` |
| PRV001 | error | 脱敏文本/结果表中不得残留已识别的姓名/医院名明文（回退补掩码） |

报告格式：`规则ID | 严重级 | 是否通过 | 异常项 + 原文片段`。
规则检查是**确定性判定**，不依赖 LLM；有 error 级异常必须明确告知，不得静默吞掉。

## 铁律

1. **只增不减**：补全不覆盖 MinerU 已识别内容。
2. **不覆盖已有文件**：输出目录中同名既有文件会被跳过。
3. **失败退回**：任一图补全失败 → 退回该图原始内容，不中断整体任务。
4. **先脱敏再提取**：阶段二绝不用未脱敏文本。
5. **数据不外传**：rapidocr 本地推理（0 网络）；MinerU/Ollama 均在内网（10.20.79.38）。
6. **阶段一结束必须停下**，等用户确认后再进入阶段二。
7. **不改动其他技能**：本技能自包含。
